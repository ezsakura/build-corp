# Чуваш Строй

Публичный сайт строительной бригады, административная панель, API и PostgreSQL. Все компоненты запускаются через Docker Compose.

## Первый запуск

1. Скопируйте `.env.example` в `.env`.
2. Укажите секреты и данные администратора. Для `DB_PASSWORD` используйте URL-safe значение.
3. Запустите `docker compose up -d --build`.

После первого запуска миграция создает схему PostgreSQL, а seed добавляет примеры объектов и новостей только в пустые таблицы.

- Сайт: http://localhost:3000
- Панель: http://localhost:3001
- Логин панели задается в `ADMIN_USERNAME`, пароль — в `ADMIN_PASSWORD`.

Порт PostgreSQL наружу не публикуется. База и загруженные фото хранятся в Docker volumes `postgres-data` и `uploaded-media`. Статусы заявок и публикация завершенных работ управляются в панели.

## Развертывание на VPS

Для production используется Caddy в профиле `production`. Он принимает HTTP/HTTPS на портах 80/443, автоматически получает и обновляет сертификаты и направляет сайт на основной домен, а панель — на поддомен.

При каждом push в ветку `main` GitHub Actions собирает production-образы и публикует их в GitHub Container Registry (GHCR). На VPS исходный код и `node_modules` не нужны: скрипт скачивает только Compose/Caddy-конфигурацию и запускает готовые контейнеры.

```bash
read -s -p "GitHub token (доступ к репозиторию и read:packages): " GH_TOKEN; printf '\n'
curl --config <(printf 'header = "Authorization: Bearer %s"\n' "$GH_TOKEN") \
  -H 'Accept: application/vnd.github.raw' -fsSL \
  -o /tmp/build-corp-deploy.sh \
  'https://api.github.com/repos/ezsakura/build-corp/contents/deploy.sh?ref=main'
unset GH_TOKEN
sudo bash /tmp/build-corp-deploy.sh
```

Перед первым запуском дождитесь успешного workflow `Build and publish Docker images` в GitHub Actions. Команда выше запросит токен для скачивания установочного скрипта из приватного репозитория; затем сам скрипт запросит GitHub username и токен с доступом к репозиторию и `read:packages`. Для classic PAT нужны права `repo` и `read:packages`; для fine-grained PAT — чтение Contents и Packages. Docker сохранит вход на VPS. Не передавайте токен другим людям. Скрипт проверит Docker/Compose и, если они отсутствуют, установит Docker Engine и Compose plugin из официального подписанного apt-репозитория на Ubuntu/Debian. Затем он спросит домены и данные администратора. DB-пароль и JWT-секрет будут сгенерированы автоматически, `.env` сохранится в `/opt/build-corp` с правами `600`, будет включен `COOKIE_SECURE=true`, скачаны образы и запущен production-профиль. Настройки компании задаются в конструкторе сайта и хранятся в PostgreSQL. При повторном запуске скрипт сохранит секреты, обновит домены и обновит контейнеры до опубликованных образов.

До запуска скрипта создайте DNS A-записи для обоих доменов на IP VPS. Откройте TCP 80/443 и SSH; UDP 443 нужен для HTTP/3. Для обновления скачайте скрипт повторно и запустите его снова; клонировать репозиторий на сервер не нужно.

Пример адресов: `https://chuvashstroy.ru` и `https://admin.chuvashstroy.ru`. Сервисы сайта и панели дополнительно доступны только на loopback-портах 3000/3001; PostgreSQL и API наружу не публикуются. Сертификаты Caddy сохраняются в volume `caddy-data`.

В обычном локальном режиме Caddy не запускается: сайт остается на `http://localhost:3000`, панель — на `http://localhost:3001`. Для локальной разработки без Docker запускайте API на порту 3002, клиент на 3000, панель на 3001; Vite проксирует `/api` и `/uploads` к API. API требует PostgreSQL и те же переменные окружения, что описаны в `.env.example`.

## Статусы заявок

- `NEW` — новая заявка сохранена в PostgreSQL.
- `UNDER_REVIEW` — заявка рассматривается.
- `IN_WORK` — заявка принята в работу.
- `REJECTED` — заявка отклонена.
- `COMPLETED` — работа завершена; для публикации нужно добавить фотографию, описание, место и срок.

## Предварительные расчеты

Типы работ, единицы измерения и тарифы редактируются в разделе «Типы работ» панели. Начальные значения демонстрационные: замените их реальными тарифами бригады до публикации. Расчет не является сметой или офертой.

## Конструктор лендинга

Войдите в административную панель и откройте раздел «Конструктор сайта». Там можно менять название, контакты, показатели, SEO-метаданные и цвета бренда; включать, скрывать, редактировать, удалять и перемещать блоки; добавлять собственные текстовые блоки; раскрывать и сворачивать настройки каждого блока; менять фотографии первого экрана, калькулятора, компании, проектов и новостей через URL или загрузку файла. Карточки портфолио и новости ведутся также в своих разделах панели.

Кнопка «Сохранить» сохраняет структуру и настройки в таблицу `LandingPage` в PostgreSQL. Изменения опубликованной страницы применяются сразу после сохранения.

## Аудит безопасности

Production API-образ устанавливает только runtime-зависимости и не содержит Prisma CLI. В dev/migration dependency graph `npm audit` отмечает high advisory для `prisma`/`deepmerge-ts`; Prisma CLI нужен только во время сборки и одноразовой миграции. Сайт и админка публикуются на loopback-портах за Caddy; база и API наружу не выставляются.
